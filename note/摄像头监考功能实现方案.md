# 摄像头监考与违规中止功能实现方案

> 状态：已按产品答复更新规则草案；账号体系规则已确认，本文描述计划，不代表功能已经实现。  
> 日期：2026-10-13  

## 1. 目标与已确认需求

本方案基于当前 FoloUp 项目设计候选人摄像头监考能力。已确认的需求如下：

1. 候选人参加面试时打开摄像头。
2. 管理员可以设置截图分析间隔，系统按间隔截取摄像头画面并交给 LLM 判断。
3. 视觉分析复用系统设置页已经配置的 LLM 接口地址、模型名称和 API Key，不额外增加视觉模型或独立密钥配置。
4. 系统设置页应提醒：摄像头监考需要支持图像输入的多模态模型；使用不支持图像输入的模型时，监考功能可能无法正常工作。
5. 每次确认违规都在候选人页面提醒；达到三次后强制结束面试，并在结果中标记因违规强制结束及具体违规。
6. 监考全局启用，管理员可配置采样间隔，默认 30 秒。
7. 违规类型包括明显手机入镜、候选人持续离开画面、第二张人脸，以及频繁看向屏幕外；同一行为连续命中合并，恢复正常 30 秒后再次出现才算新事件。
8. 单张截图达到高置信度即可判定一次违规，不要求连续两张确认；高置信度门槛可由管理员设置。
9. 摄像头授权失败时不允许开始面试；视觉模型连续调用失败不暂停、不结束面试，只保存截图并记录技术故障，供人工查看。
10. 普通采样截图和违规截图都需要保存 7 天。
11. 第三次违规中止仅作为监考风险标记，结果仍由 HR 人工复核，不自动判定不录用。
12. 设置页需要提供固定非个人样例图的视觉输入测试按钮。
13. 后台登录与管理员授权属于本功能上线前置条件；账号体系只有管理员一种角色。
14. 需要单独增加一个简单的管理员账号体系，目标是防止普通访问者直接进入后台，不开放普通用户角色、公开注册或角色细分。

已确认：管理员登录使用账号密码，初始账号和密码为 `admin` / `admin`；所有能登录的账号均拥有完整后台权限；不提供用户创建、普通用户权限、账号角色管理、邮件找回或登录失败锁定策略；会话有效期按 7 天设计；采样间隔允许 5 至 60 秒。

## 2. 当前项目实现边界

- 候选人面试页为 `src/app/(user)/call/[interviewId]/page.tsx`，通过页面同意门后挂载 `src/components/call/index.tsx`。
- 实时语音、麦克风和 WebSocket 生命周期位于 `src/components/call/index.tsx` 与 `src/components/call/realtimeClient.ts`。面试逐字稿当前主要在完成面试时提交。
- 候选人同意门和本地同意版本位于 `src/app/(user)/call/[interviewId]/consent-gate.tsx` 与 `consent.ts`；候选人专属邀请的同意记录写入 `consent_record`。
- 管理员可配置的 LLM 参数由 `src/components/settings/settingsForm.tsx` 提交至 `src/app/actions/settings.ts`，服务端保存在 `app_setting`；`src/lib/llm.ts` 统一发起 OpenAI 兼容的 Chat Completions 请求。
- `src/lib/llm.ts` 当前消息 `content` 是纯文本类型，需扩展图文消息构造；服务端调用仍应沿用现有的接口地址、模型、密钥、超时配置。
- `src/lib/data/call-sessions.ts` 已有服务端会话开始、结束和 SQLite 幂等保护；面试结果展示位于 `src/components/call/callInfo.tsx`，候选人状态列表位于 `src/components/dashboard/interview/candidateManager.tsx`。
- 当前 HR 后台与设置动作没有管理员身份认证/角色校验。若要让“管理员设置”成为实际权限边界，必须先补充后台认证或明确由部署层提供访问限制。
- 当前未发现现成的自动化测试脚本；实施时需要为关键数据事务、API 校验和结束流程补充可重复的测试。

## 3. 总体实现原则

1. 浏览器只负责摄像头授权、预览、从视频流截取压缩单帧、展示提示和上报当前逐字稿快照；API Key、模型调用、违规计数及结束决定全部留在服务端。
2. 截图内容只用于本次视觉分类，不上传整段视频、不启用人脸身份识别、不将摄像头图像用于面试能力评分。
3. 模型输出是风险信号，不是对候选人主观意图的事实认定。单张图片达到配置的高置信度门槛才可计次；低置信度、模型错误或无法判断不得增加违规次数。
4. 同一持续行为不得因为连续多张截图而反复计数；同类行为恢复正常至少 30 秒后再出现，才可创建新的违规事件。
5. 第三次事件的计数、违规事件留档和服务端结束状态必须处于一个原子数据事务中，不能只依赖浏览器收到提示后自行结束。
6. 候选人应在面试前清楚知道摄像头用途、采样频率、图片会发送给当前配置的 LLM 服务进行分析、违规规则、保存 7 天的信息范围和联系渠道。

## 4. 端到端流程

### 4.1 管理员配置

在现有 `/settings` 页面增加“摄像头监考”设置区：

- 监考功能全局启用，所有新面试适用同一开关与间隔，不提供岗位级覆盖。
- 截图分析间隔（秒）由管理员配置，默认 30 秒；最小值和最大值需由产品确认并由服务端校验。
- 高置信度阈值由管理员配置；建议默认 `0.85`，服务端校验合法范围，并在会话开始时冻结本场实际阈值。
- 显著提示当前 LLM 必须支持图像输入。模型能力无法仅凭模型名称可靠推断，因此提示是兼容性告知，不应显示成自动验证通过。
- 保存与读取继续复用现有 `app_setting` 仓储；只有经确认的管理员才可读取/修改这些设置。

建议提示文案：

> 摄像头监考会按设定间隔截取候选人画面，并通过当前配置的 LLM 接口进行分析。请确认所选模型支持图像输入（多模态）；不支持图像输入时，摄像头检测可能无法工作。图片会发送至当前 LLM 服务商，请在启用前确认相应的数据处理与保存规则。

增加“测试图像输入”按钮，用固定的非个人样例图片请求当前 LLM，验证当前端点是否接受图像输入。它只能验证接口基本兼容性，不能证明模型对真实违规场景判断准确。

### 4.2 面试前告知与摄像头预检

1. 在同意门中新增独立的摄像头监考告知与同意项，并升级同意文案版本；同意服务端留痕应关联候选人、岗位、call_id、文案版本和同意时间。
2. 在候选人点击“开始面试”的用户手势中请求 `getUserMedia({ video: ... })`，展示摄像头预览和就绪状态，再开始实时语音连接。
3. 浏览器拒绝授权、设备不存在或页面不是安全上下文时，显示可操作的中文错误并阻止开始面试；不提供跳过摄像头的非监考入口。
4. 摄像头预览只存在于候选人当前页面；不录制连续视频，只保留按间隔取得的静态截图。

### 4.3 面试中截图与视觉分析

1. 面试服务端开始成功后，按 30 秒默认值或管理员设置启动单飞截图循环；前一次分析尚未返回时不并发堆积截图请求。
2. 使用隐藏 `<video>` 和 `<canvas>` 仅绘制当前单帧，缩放到满足模型识别需要的最小分辨率，并导出 JPEG/WebP。具体尺寸、质量和请求体上限需通过真实模型试调确定。
3. 每张采样截图都上传服务端，保存图片并记录对应采样时间、模型分析状态和结果；违规事件关联触发它的截图。截图及逐字稿快照通过 `POST /api/proctor/analyze` 提交，接口验证 call_id、会话状态、短时会话凭证、间隔限速、媒体类型和最大字节数。
4. 服务端使用现有 `chatCompletion` 和 `getRuntimeAppSettings()` 读取已配置的 base URL、模型与密钥，将一张图片作为 OpenAI 兼容 `image_url` 内容段提交。不得把 LLM 密钥发给摄像头代码或新 API 的浏览器响应。
5. 提示词要求只返回受限 JSON：`status`（`violation` / `clear` / `uncertain`）、`violationType`、`confidence`、简短可复核说明。手机、离开画面、第二张人脸、频繁看向屏幕外均按已确认的范围判断；仅单张达到管理员配置高置信度阈值的结果计次。
6. 当前 LLM 的 JSON 模式能力可能与图像消息兼容性不同。视觉请求需验证当前接口行为；必要时视觉调用使用普通文本输出并由 `extractJson` 解析，不能因 `response_format` 不兼容而误判候选人违规。
7. 采样间隔、违规阈值、图像尺寸/质量及实际使用的模型名冻结到会话元数据，避免面试中管理员改设置导致规则漂移。
8. 以 20 分钟面试和 30 秒间隔估算，约产生 40 张截图和 40 次视觉请求/人；图片存储容量和模型费用需要纳入运维预算。

### 4.4 违规计数、提醒与强制结束

1. 只有服务端完成分类并命中已确认的违规规则后，才创建一条 `proctor_event`。`uncertain`、`clear`、API 超时、限流、模型不支持图片和 JSON 解析错误都不增加计数。
2. 服务端在 SQLite 立即事务中确认会话仍然活动、去重当前事件、写事件记录并读取/更新该 call_id 的累计事件数。
3. 单张图片达到高置信度门槛并确认违规后，API 返回当前次数和违规说明，页面显示醒目但不阻断面试的提示，例如“监考提醒 1/3：检测到疑似手机，请将手机移出画面”。“频繁看向屏幕外”按最近 60 秒内至少 2 次高置信度目光偏离，再由下一张截图确认后计为一次违规。
4. 第 3 次确认违规：同一事务把 `response.is_ended` 置为 1，保存结束时间、服务端时长、`end_reason = proctoring_terminated`、三次事件摘要，并更新专属邀请为 completed。服务端返回终止结果后，浏览器立即关闭语音 WebSocket、停止音频和摄像头轨道并展示结束页。
5. 为确保服务器中止时逐字稿不丢，截图分析请求同时携带最新结构化逐字稿快照；服务端仅在受信会话有效时保存/更新该快照，并在第三次事件的结束事务里作为最终逐字稿。逐字稿请求体设上限，并验证角色、文本长度和偏移数据结构。
6. 候选人手动结束、时间到期、语音连接中断与第三次监考中止可能并发。服务端需使用现有幂等结束保护，确保最终只保存一个结束原因；若第三次违规事务已经提交，建议优先保留 `proctoring_terminated`。
7. 面试结束后继续触发既有评分流程；监考类别、次数和事件说明不得被混进能力分数或沟通能力评分。

## 5. 建议的数据结构与接口

### 5.1 系统设置

继续使用 `app_setting`，拟增加：

| 键 | 类型 | 建议用途 |
|---|---|---|
| `proctoring_enabled` | `0/1` | 全局监考开关，所有新面试统一生效 |
| `proctoring_interval_seconds` | 整数文本 | 全局采样间隔，默认 30 秒；允许范围待确认 |
| `proctoring_confidence_threshold` | 小数文本 | 高置信度阈值，建议默认 `0.85`，管理员可设置 |
| `proctoring_max_violations` | 整数文本 | 固定为 3，不作为日常设置项 |

实际使用的全局开关、采样间隔和违规阈值在会话开始时冻结到会话快照，管理员修改只影响后续新面试。

### 5.2 采样图片与违规事件表

由于产品要求保存普通截图和违规截图 7 天，建议分离采样元数据与图片二进制：图片存入应用主机本地非公开目录，SQLite 只保存随机存储键及元数据，不把 Base64 或大 BLOB 放入 `response.details`。

建议增加 `proctor_capture` 表记录每次采样：

| 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `call_id` | 面试会话编号 |
| `captured_at` | 服务端确认接收的采样时间 |
| `storage_ref` | 私有存储中的随机对象键，不是公开 URL |
| `analysis_status` | `pending` / `completed` / `failed` |
| `analysis_result` | 受限 JSON 分析结果或安全的错误分类 |
| `retention_until` | 图片及记录的计划删除时间，默认采样时间后 7 天 |

所有图片都必须有管理员鉴权的查看路径。日志、异常堆栈、分析请求和 API 响应不得意外输出图片 Base64 或本地物理路径。

建议增加 `proctor_event` 表，至少包含：

| 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `call_id` | 面试会话编号 |
| `event_type` | 服务端白名单违规类型 |
| `occurred_at` | 服务端生成的事件时间 |
| `confidence` | 经服务端校验的模型置信度 |
| `summary` | 限长的中文事件说明 |
| `strike_number` | 本事件确认时的累计次数 |
| `capture_id` | 关联触发该违规的 `proctor_capture.id` |

SQLite 事务负责写入采样元数据及违规事件引用。图片文件写入与数据库提交不是同一事务，实施时需设计临时文件、成功提交后原子改名及失败清理，避免数据库指向不存在的图片或遗留孤儿文件。

当前 Docker Compose 未为截图目录定义持久卷。第一期采用主机私有目录，并在 Docker Compose 增加截图目录持久卷；需增加 7 天到期自动清理任务，避免磁盘持续增长。图片目录必须位于 `public/` 之外，禁止静态 URL 直接访问。

SQLite 写入与图片文件创建不是同一事务。实现应采用临时文件写入、校验、原子改名，再提交数据库元数据；数据库提交失败时清理孤儿文件，进程崩溃后的遗留临时文件由定时清理任务回收。

### 5.3 面试结果

扩展 `CallEndReason` 和结果数据：

- 新结束原因：`proctoring_terminated`。
- `response.details.proctoring`：本场是否启用监考、采样间隔、累计确认次数、违规类型摘要、事件表引用。
- `proctor_event` 作为逐次事件的查询来源；`details` 保留结果页所需的简明最终摘要。
- 历史 response 没有 `proctoring` 字段时按“未启用/无记录”展示，不能影响历史结果页。
- HR 可按时间查看本场全部采样截图、模型分析结果和技术故障；违规事件能定位到对应截图。

### 5.4 服务端接口建议

- `POST /api/proctor/analyze`：校验受信会话、大小与速率后调用当前 LLM；记录已确认事件，返回 `{ status, strikeCount, maxStrikes, event, terminated }`。
- 设置保存 Server Action：增加 interval/enabled 校验，并补齐管理员授权检查。
- 会话结束数据层：扩展结束原因、原子累计事件及第三次违规强制结束路径。

具体路由命名可按实施时现有 API 习惯调整。任何由客户端提交的 `strikeCount`、`is_ended`、`end_reason` 都不能作为服务端事实直接落库。

### 5.5 账号体系与权限

账号体系作为独立前置阶段实现，至少包括：

- `admin_account`：账号编号、唯一登录名、密码哈希、启用状态、是否已完成首次改密、创建时间、最后登录时间。系统只有管理员账号，不保存角色字段，也不建立普通用户表。
- `auth_session`：随机不可预测的会话令牌哈希、账号编号、创建时间、过期时间、撤销时间及必要的客户端摘要。浏览器仅保存 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie，不将明文令牌放在 `localStorage`。
- 登录、退出、当前账号查询、会话失效和密码修改流程；密码错误使用统一提示。
- 服务端 `requireAdmin()` 鉴权边界。所有后台页面、设置 Server Action、API、HR 数据读取以及截图读取都需要服务端做访问校验，不能只靠隐藏菜单。
- 中间件或服务端布局负责未登录跳转；API/Server Action 仍要独立检查权限，不能把页面跳转当作唯一防线。
- 密码以成熟的单向哈希保存，优先 Argon2id；若不增加原生依赖，则评估使用 Node 内置 `crypto.scrypt`、独立随机盐、版本化参数。禁止保存明文或可逆加密密码。
- 首个管理员固定初始化为账号 `admin`、密码 `admin`；实现时数据库只保存密码哈希，不保存明文密码。
- `admin/admin` 只能作为开发/首次初始化凭据。首次成功登录后必须要求管理员修改密码；生产环境若仍使用默认密码，后台应显示高风险警告，部署文档也必须明确要求修改。
- 登录会话采用 7 天有效期，退出时服务端撤销；密码修改后撤销该管理员的其他会话。
- 本期不实现公开注册、用户创建、管理员角色细分、邮件找回和连续失败锁定；仍应对登录接口做基础请求限流，避免默认账号被无限暴力尝试。

管理员是唯一后台身份，并拥有所有后台权限：

| 功能 | 管理员 |
|---|---:|
| 登录后台 | 是 |
| 创建和管理岗位 | 是 |
| 查看候选人和面试结果 | 是 |
| 修改 LLM / 监考设置 | 是 |
| 查看截图、监考事件和技术故障 | 是 |
| 修改管理员密码 | 是 |

不增加第二种管理员角色，也不提供账号管理页面。账号密码修改由管理员本人完成，并保护系统至少保留一个可登录管理员。

## 6. 候选人与 HR 界面

### 候选人端

- 面试前：监考说明、摄像头权限、实时预览、摄像头就绪/失败状态。
- 面试中：摄像头使用状态、采样分析中状态、每次违规即时提示和 `当前次数/3`。视觉调用连续失败时不暂停、不停止面试；继续截图并显示“视觉分析暂不可用，截图已保存，等待人工复核”的非阻断提示。
- 第三次违规：明确说明面试已因监考规则中止，显示已确认的具体事件及后续联系人；不展示“作弊者”等对主观意图的定性。
- 结束时停止 `MediaStreamTrack`，包括正常结束、页面卸载和语音异常结束路径。

### HR 结果端

- 在结果详情中显示醒目的“因监考规则强制中止”标签。
- 展示每次违规的时间、类型、模型说明和置信度，以及监考设置快照。
- 不把该标签自动映射成“不录用”；是否需要人工复核状态或申诉/备注字段，待确认。
- 展示每张已保存的采样截图、采样时间、分析状态、违规关联和技术错误；图片读取接口逐次校验管理员权限，不额外记录查看审计。

## 7. 错误处理与安全边界

- 摄像头权限、浏览器支持、安全上下文：候选人开始前预检并给出修复提示。
- 单次视觉 LLM 超时、429/5xx、图像格式不兼容或响应解析失败：不计违规，记录技术故障并继续截图。连续失败 3 次后仍不暂停、不停止、不改变面试计时，只保留截图和故障记录，交由后台人工考核；后续视觉调用恢复时清零连续失败计数。
- 技术故障不构成违规，不触发累计三次强制结束；`proctor_service_event` 记录每次失败、连续失败计数、错误分类和恢复时间，供管理员后台查看。
- 服务端按 call_id 强制间隔限速，不接受客户端缩短管理员设置的采样间隔，不允许并行积压分析请求。
- 图像采用有界尺寸和体积；服务端限制 JSON 请求体，拒绝非 JPEG/WebP 图像和超限数据。
- 会话授权使用服务端生成的短时随机凭证，绑定 call_id 和用途；不能仅凭可见 call_id 允许任意人给他人会话提交帧或违规事件。
- 面试设置、采样图片、事件列表和故障记录需要管理员鉴权。后台登录与管理员授权是本功能上线前置，不接受仅隐藏页面但 Server Actions/API 可直接调用的保护方式。
- 候选人图像发往配置的 LLM 服务商前，需核对该服务商的数据处理条款、地域、日志/留存策略和密钥权限；此文档不是法律意见。
- 若图像存储或自动化判断对候选人产生重大影响，上线前进行个人信息保护影响评估并记录；监考结果作为风险信号交由 HR 复核，不作为唯一自动化录用/拒绝依据。

## 10. 规则确认结果

### 已确认

1. 高置信度阈值可以在管理员面板设置；建议默认 `0.85`，实际值在面试开始时冻结。
2. “频繁看向屏幕外”按最近 60 秒内至少 2 次高置信度目光偏离，再由下一张截图确认后计为一次违规。
3. 视觉模型连续失败 3 次不暂停、不停止、不改变面试计时；继续截屏并保存，后台记录故障，最后由人工考核。技术故障不计入违规次数。
4. 不存在视觉故障暂停阶段，不需要暂停/恢复语音或冻结面试计时的实现。
5. 普通截图、违规截图和对应分析元数据保存 7 天，之后自动删除。
6. 截图直接保存在应用主机本地私有目录，不放进 `public/`，Docker 部署需要挂载持久卷。
7. 账号体系只有管理员一种身份，不存在普通用户角色，也不细分管理员角色。
8. 图片查看、下载和删除不需要额外记录审计日志，但仍必须经过管理员权限校验。
9. 账号体系需要作为单独的前置阶段实现，所有后台能力统一由管理员账号访问。
10. 视觉输入测试失败只显示警告，允许管理员保存配置和开启监考。

账号相关规则已经确认，可以冻结 `admin_account`、`auth_session`、后台路由保护和统一管理员权限接口。实施时所有新加的代码注释继续使用中文。
